# Security policy and deployment scope

This release supports a single-host educational service. It has device-token profile access, separate administrator authentication, transactional SQLite storage, a 1 MiB request-body limit, input validation, and process-local rate limiting.

## Private profiles

Tokens contain 32 random bytes generated by Python's `secrets` module. Only SHA-256 token hashes are stored server-side; comparisons use `compare_digest`. A token authorizes access to exactly one profile. Profile responses never include the stored hash. Creating a profile is intentionally public and rate-limited.

Tokens and drafts are stored in browser local storage. This protects profiles from unauthenticated API callers but does not protect against malicious browser extensions, a compromised device, or successful same-origin script injection. Use HTTPS for remote hosting and keep access backups private. There is no account registration, email verification, or automated password recovery.

## Administrator access

Set a randomly generated `ADMIN_API_KEY` of at least 32 characters on the backend only. Without one, profile listing and model-management endpoints fail closed. Do not put it in frontend configuration, URLs, source control, or screenshots. The recovery script requires local access to the storage directory and rotates a profile token.

## Operational limits

- Run one API worker: rate limits and active-model state are process-local. Horizontal scaling requires shared rate limiting and model coordination.
- Keep SQLite and model volumes private and backed up. Import preserves legacy JSON files; explicitly deleting a profile also removes its matching legacy JSON file. Independent external backups require their own retention policy.
- Retraining is disabled by default. Review data provenance and metrics before enabling it or promoting artifacts.
- Joblib/pickle files are executable deserialization formats. Load only trusted artifacts, and review their hashes and provenance.
- Container configuration does not supply HTTPS, account identity, distributed abuse protection, or a managed backup service.
- The default container omits the optional Anthropic SDK. Installing it and supplying an API key enables external transmission of assessment context for explanations; disclose that to users before enabling it.

## Reporting

Use GitHub private vulnerability reporting when enabled, or contact the repository owner privately. Do not include real tokens, private profiles, or API keys in a public issue. Dependency updates are proposed through Dependabot; CI runs npm and Python dependency audits.
